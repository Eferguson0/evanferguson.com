The problem

Working within Customer Success, I spend a fair amount of my day relaying information. With LLMs being great at summarizing and drafting content, there was a clear use case to build a simple UI that would allow me to quickly take a message received, add context for actions that need to be taken based on the request, and have an LLM draft a new message for a given channel. This would cut out the low-value work of drafting, and allow for more capacity of high-value work like strategy.

The solution

Relay essentially allowed content drafting iteration to move outside of the LLM apps and into an interface where the user could more easily iterate/edit the message. Relay had an interface where the user pasted the source message/context (email, Slack, Google Docs, etc.), added relevant context, and select the desired channel. For example, if a client emailed me with a request, I could note 'forward to engineering and include key fields', and Relay would draft it to #engineering. The goal was to remove the low-value first-draft work and accelerate getting the final draft sent.

To try to avoid AI slop, I implemented a lightweight memory system. Whenever a user copied a draft, Relay treated that as a proxy for approval and used GPT-4 to log its purpose, tone, structure, and other stylistic patterns in Supabase. When drafting a similar message later, an agent would pull the three most recent messages with the same type and purpose, create a compact style profile from them, and add it back into the prompt.

By the time I finished the MVP, Anthropic had announced MCP. I found more value in the flexibility of MCP-based workflows than continuing to invest in Relay’s editable UI.

Agents

Relay had several specialized agents to process/draft information, and learn the user's writing style. Each was a CrewAI agent with a single task, run in sequence:

  • Message purpose agent: Before drafting, this agent classified the intent of the received message (question, update, request, agenda, etc.), so the draft would better match the situation.
  • Slack agents: Two agents. The first reviewed the content of a message and suggested the most appropriate Slack channel for it. The second drafted the Slack message from the provided context.
  • Email agents: Three agents. The first to identify the appropriate recipient's email, the second to write a concise subject line, and the third to draft the actual email content.
  • Message refinement agent: This agent would help users revise a draft, using the original context and user feedback to make targeted changes without rewriting everything from scratch or losing context.
  • Style learning agent: Once a user finalized a message, this agent analyzed its purpose, tone, structure, and writing patterns to gradually develop a better understanding of the user's communication style.

I opted to keep orchestration in the form of selecting the desired channel in the UI, rather than having a crew review and pass off. Implementing a crew would have been a cool UX, but slower and overkill.
