The problem

Customer Success roles spend a significant portion of the day relaying information: reading an incoming request, deciding what needs to happen, and drafting a message to the right person on the right channel. A client email asking for a fix, for example, has to be summarized and forwarded to engineering in Slack with the key details intact. LLMs handle summarizing and drafting well, but iterating on a draft inside LLM chat apps is clunky, and context has to be copied in by hand for every message. The goal of this project was to build a simple interface that takes a received message, seeds context on the actions it requires, and drafts the message for a chosen channel, freeing up time for higher-value work like strategy.

The solution

Relay moved drafting out of LLM chat apps and into an interface built for editing. As a first version, the user pasted the source message (email, Slack, Google Docs, etc.) by hand, added instructions, and selected a channel; the ideal state was direct API connections to each source. Given a client email with a request, for example, a note like "forward to engineering and include key fields" produced a draft for #engineering, ready to edit and send.

To keep drafts from sounding generic, Relay used a lightweight memory system. Copying a draft counted as approval: GPT-4 logged its purpose, tone, structure, and other stylistic patterns in Supabase. When drafting a similar message later, an agent pulled the three most recent messages with the same type and purpose, built a compact style profile from them, and added it to the prompt.

By the time the MVP was finished, Anthropic had announced MCP. MCP-based workflows offered more flexibility than Relay’s editable UI, so further investment in Relay ended there.

Agents

Relay had several specialized agents to process/draft information, and learn the user's writing style. Each was a CrewAI agent with a single task, run in sequence:

  • Message purpose agent: Before drafting, this agent classified the intent of the received message (question, update, request, agenda, etc.), so the draft would better match the situation.
  • Slack agents: Two agents. The first reviewed the content of a message and suggested the most appropriate Slack channel for it. The second drafted the Slack message from the provided context.
  • Email agents: Three agents. The first to identify the appropriate recipient's email, the second to write a concise subject line, and the third to draft the actual email content.
  • Message refinement agent: This agent would help users revise a draft, using the original context and user feedback to make targeted changes without rewriting everything from scratch or losing context.
  • Style learning agent: Once a user finalized a message, this agent analyzed its purpose, tone, structure, and writing patterns to gradually develop a better understanding of the user's communication style.

I opted to keep orchestration in the form of selecting the desired channel in the UI, rather than having a crew review and pass off. Implementing a crew would have been a cool UX, but slower and overkill.
